# Lammi — Settings changes

PR: `feat: implement settings` · Branch: `feat/settings` · Base: `main` at `d958c6e`

This document records every file created or modified for Lammi's
**Settings** assignment, how each file uses the existing shared code, and
what is still needed from other developers. Profile is a separate PR
(`feat: implement profile`, documented in `docs/lammi-profile-changes.md`).
The two PRs share no files and can be merged in either order.

## What Settings does

- **Theme:** System, Light or Dark, applied to the whole app through the
  existing `themeModeProvider` and `AppTheme`.
- **Language:** shows the current language and switches between English and
  አማርኛ through the existing shared `selectedLanguageProvider`, which also
  saves the choice to the signed-in user's profile.
- **Notifications:** an on/off preference held in memory. No notifications
  are sent.
- **Shortcuts by role,** to existing routes and screens only:
  - Owner: My Listings
  - Tenant: Favorites and Viewing Requests
  - Admin: Moderation
- **Sign out:** a confirmation dialog, then the existing
  `CurrentUserNotifier.signOut()`, then Login. Signed-out users get a
  "Sign in" entry instead.

## Files

All paths are under `lib/features/profile/` unless shown in full.

### Modified

#### `presentation/providers/theme_mode_provider.dart`
- **Status:** Modified (authorized handoff, see above).
- **Purpose:** `themeModeProvider` now derives `ThemeMode.system`, `light` or
  `dark` from `appSettingsProvider`, instead of always returning
  `ThemeMode.system`.
- **Why necessary:** `KirayBetApp` (`lib/app.dart`) already applies
  `ref.watch(themeModeProvider)`. Keeping the name and the
  `Provider<ThemeMode>` type means `app.dart` needs no change.

#### `presentation/screens/settings_screen.dart`
- **Status:** Modified (Lelisa's placeholder, changed with approval).
- **Purpose:** `SettingsScreen.build` returns `const AccountSettingsScreen()`.
- **Why necessary:** `app_router.dart` already sends `/profile/settings` to
  `SettingsScreen`, so Settings is reachable without router changes.

### Created

#### `domain/app_settings.dart` and `domain/app_settings.freezed.dart`
- **Purpose:** The `AppSettings` freezed model (`themePreference`,
  `notificationsEnabled`) and the `AppThemePreference { system, light, dark }`
  enum. The `.freezed.dart` file is generated by freezed 4.0.3, the project's
  existing version.
- **Why necessary:** The settings state. The domain layer stays independent
  of Flutter, and the mapping to `ThemeMode` is in `theme_mode_provider.dart`.
  The language is deliberately not stored here, because the shared
  `selectedLanguageProvider` owns it.

#### `presentation/providers/app_settings_provider.dart`
- **Purpose:** `appSettingsProvider` (`AppSettingsNotifier`), which holds the
  settings in memory, with `setThemePreference` and `setNotificationsEnabled`.

#### `presentation/screens/account_settings_screen.dart`
- **Purpose:** `AccountSettingsScreen`, the Settings UI described above.
- **Interaction:** Reads and updates `appSettingsProvider`,
  `selectedLanguageProvider` and `currentUserProvider`. Links use the
  existing `RoutePaths.myListings`, `favorites`, `viewingRequests`,
  `moderation` and `login`. It reuses `AuthenticationStrings` (`language`,
  `english`, `amharic`, `signIn`, `moderationTitle`) and `ListingStrings`
  (`myListings`, `viewingRequests`). These are read only, not modified.

#### `presentation/settings_strings.dart`
- **Purpose:** `SettingsStrings`, holding every new user-facing string on the
  Settings screen.
- **Why necessary:** Follows the project's per-feature strings convention.
  The screen contains no hardcoded text.

## Known limitations

- Theme and notification preferences reset when the app restarts.
- The notifications switch stores a preference only.
- Text stays English until project-wide localization exists.
- Settings is opened from the Profile screen's settings icon, which arrives
  with the Profile PR. Until then it is reachable at `/profile/settings`.
